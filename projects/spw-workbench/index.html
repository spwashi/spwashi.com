Spw Workbench

Spw is a small notation I write ideas in. The workbench keeps its parser (spw-seed), runtime (spw-runtime), language server (spw-lsp), CLI (spw-cli), and editor plugins in one system mounted at .spw/_workbench (bcf0da18).

Start across spw.quest

spw.quest teaches the twelve marks, four brace containers, four #/~ particles (#>, #:, #!, ~#), Persona@ perspective holders, and the /llms.txt format across worked scenes that travel directly to factshift.center and this site.

One kernel, isolated physics

Structural syntax stays inside an immutable Seed record in spw-seed, while charges, lens focus, and ink stay in external host profiles. Callers pick lexing, AST, and trace depth via eventPolicy (none, diagnostics, or trace) instead of duplicating scanners.

Touch it live & build next

Type Spw into the literal parser (running the bundled bcf0da18 reader), read the P0–P3 agent development queue and open parsing issues, or browse source on GitHub.

The workbench is an organelle, not a center: this site owns .spw/, the workbench owns .spw/_workbench, and either can be upgraded or removed without making the other illegible. The site mounts it at bcf0da18 (2026-11-16).

Project direction

As of November 19, 2026, workbench work unifies parsing, container-order reading, highlighting, and editor tooling behind one parameterized kernel—see the agent queue below.

theme@[neutral-paper]{auto}(reading)<systems>

Consumers across spwashi.com, spw.quest, and factshift.center share this kernel contract while keeping domain-specific readings local.

For systems and Glass Console profiles: eventPolicy: 'diagnostics' skips trace generator allocations while tokenSpans() drives every browser highlighter from kernel tokens.

For Studio and editorial readers: Persona@ perspectives, <prose> beats, and inline scene notation parse into inspectable structure shared across creative tools.

Parameterized parse depth

Commit bcf0da18 adds eventPolicy (none, diagnostics, trace) to spw-seed. Callers that skip rule traces avoid per-step generator allocations without changing tokens, ASTs, or errors — dropping a 153 KB surface parse from 715.6 ms to 105.8 ms.

Kernel tokens for every highlighter

Browser syntax highlighting in spw-code.js and the literal parser now paints directly from kernel tokens via tokenSpans(), retiring duplicate regex scanners that drifted on #! intent tags, compound prefixes (~^light), quoted headings (^seed["Title"]), and postfix Persona@ perspectives.

Seed purity vs. host physics

Structural coupling (token spans, brace pairs, container depth) stays immutable inside Seed records, while charges, resonance, lens focus, and spoken/earcon renderers stay in external host profiles across spwashi.com, spw.quest, and factshift.center.

Scoped contexts & uniform braces

Next architectural targets replace file-wide rewinds and per-sigil special cases with container-scoped parsing contexts, stack-aware digraph handling (extending )) to >>, <<, ((, and comparisons), and one prefix/postfix combinator algebra.

  • Greedy digraph priority beats bracket-stack context. Measured live at bcf0da18: nested generics (list<Module<T>>), double-grouped math (O((V + E) log V)), and predicates (?keep{qty > 0}, ?[latency <= 400]) degrade to Prose; unquoted URLs (link = https://spw.quest) turn //spw.quest into a COMMENT token and drop the host. (workbench asks · practicality cache)
  • Tokenizer drops unrecognized glyphs & trips on escaped quotes (3 corpus files, 8 errors). Backslash escapes (\", \') inside CLI command probes, negative numbers (x = -5), and unquoted Unicode punctuation or math symbols (…, ≤, ±, ∞) raise Unexpected character tokenize errors, drop the symbol from the token stream, or trigger Unterminated string literal and downstream degradation in wip.spw, factshift-paste-grounding-2026-11.spw, and factshift-tooling-2026-11.spw.
  • Inline arrows, contours, and unclosed backticks trigger prose-degradation (9 corpus files). Unclosed inline backtick spans in attribute notes (comparison-differentials.spw, runtime-goals-pipeline.spw), morphism arrow keys (authored -> parsed: in semantics-rigor.spw), bare > contour chains (interaction-paint-cost-2026-09.spw), multi-line ?< ... >[reg=stream] blocks (spw-language-utilization-2026-07.spw, recursive-improvement.spw), and => or == operators inside spec blocks (modules.spw, thermodynamics.spw) halt structured parsing cleanly into Prose warnings.
  • Trailing units, regex slot readers, and silent channels still split consumers from the kernel. A percent unit glued to a number (%errors[0.1%]) parses clean yet tokenizes the trailing % as OPERATOR:% (keyword), inflating measure counts. Site search still keeps a non-recursive {([^}]*)} matcher alongside kernel parses in expression-query.js, leaving 9 of 27 herbarium specimens partial; readLine leaves top-level -> and ~> joins unread while parsing them inside {body}; PAIR_SOUND/TEXTURES leave < > silent despite spokenLine naming it; and WebStorm/IntelliJ regex folders still shadow LSP documentSymbol, which itself reparses open buffers.

What to develop next (agent queue)

If you are an agent or engineer working on spw-workbench, this queue turns live evidence from spwashi.com (1,322 .spw files, 1,035 HTML expressions), spw.quest (157 worker tests), and factshift.center into ranked work packages with minimal repros and acceptance checks.

P0 · spw-seed Parser & AST Uniformity

  • Container-order & prefix-body parity: Read [mode], {body}, (scene), and <concept> in any order as one expression (word<concept>(scene)[mode]{body} currently splits into 2), and expose bodies uniformly across prefix operators (~launch[soft]{...}<audience> and ?page(phone)[slow]{...}<audit> currently wrap into Capsule without Operation + body).
  • Single-expression Persona@ binding: Parse both editor@cut[rough]{pacing ~> sound}<reel> and maya@[picture]{pacing, sound_lock}(friday)<cut> as 1 perspective-bound expression instead of 2 top-level expressions.
  • Stack-aware digraphs & lossless lexer: Extend the )) guard to >>, <<, ((, <=, >=, =>, and // (URLs); stop dropping - (x = -5), ≤/±/∞/…, or choking on \"/\'; lex trailing % on numbers (%errors[0.1%]) as unit, not OPERATOR:%.

P1 · spw-cli & Shared Parse Cache

  • Content-addressed scan memo: Key corpus scans on (roots, sha256(content), dialect) and apply projection flags like hubTop after reading — ending the 28-product / 87 MB unshared memo split between census, graph, measure, and query.
  • One AST facts module + emitted JS: Ship emitted JS beside TS to remove the ~1 s tsx CLI boot cost, and expose one shared facts extractor (citations, anchors, annotations, expressions, wonders) that CLI, LSP, and spw-workbench-reader.js all consume instead of regex-first selectors.
  • Bounded recovery & stray-backtick precheck: Flag unbalanced backticks before full recovery so a single syntax typo never multiplies parse time 7×, and accept .agents/plans as a declared root with tier tags (authored, generated, archived).

P2 · spw-lsp & Editor Plugins

  • Warm parse reuse in outlineFromSource: Pass the server's held parse into documentSymbol (currently 267–510 ms reparse vs. 3–8 ms for folding/tokens) so IntelliJ/WebStorm can retire its line-regex outline/folder that breaks on apostrophes in backticks and mid-line #.
  • File-scoped @alias & @handle#fragment binder: Wire definition, references, and rename across file aliases (3,977 declarations, 2,947 uses on this site) and resolve fragments without turning #anchor into part of the filename.
  • Live buffer instruments & cost cards: Route IDE Spw Instruments (spw/formContext, spw/resonance, spw/geometry) through the warm LSP instead of spawning CLI on saved files (2.9 s), and surface meaning-first hovers plus dormant-expression wake actions.

P3 · Cross-Domain Contracts

  • Recursive slots & top-level ~>/-> in readLine: Replace flat {([^}]*)} slot matching (fixes 9/27 partial herbarium specs and unblocks postfix ~> on HTML routes), and add < > concept timbre to PAIR_SOUND/TEXTURES beside spokenLine.
  • operator.table/1 + dated mnemonic glosses: Ship one canonical operator table paired with a dated mnemonic gloss layer (distinguishing spirit-sequence mnemonics from canon types) so spwashi.com, spw.quest, factshift.center, and lore.land never drift.
  • inquiry.loop/1 & canonical still-line slot contract: Land runnable wonder receipts (?["..."]{ !probe{} } → result_ref) and one parseable still-line shape across screenshot harnesses, captions, and factshift.center scrub rails.

What came before

This is not the first Spw parser. spw-client (2020) was an interface for an early Spw; ts-language built grammars; spw-editor was a text editor for the language; spw-js (2021–2024) held the grammar, parser and runtime; spw-parser (2022–2025) rewrote part of it from scratch; parser (2023–2024) put one in the browser. The workbench gathers what those tried into one mountable piece. The longer story is on the website field guide, and every repository is on the projects hub.

?taught

What using it taught

This site keeps .spw/workbench-report.spw addressed to the workbench, measured on a mounted consumer rather than theorised. Between September 29 and November 17, 2026, walk, alignment, and trace fixes landed upstream.

Resolved findings from the consumer report include walk isolation, parse()/parseExpression() alignment, ~> project-joins, spw lint/resolve/fingerprint, )) n-range closing, and zero-trace eventPolicy modes, while the open cases above remain tracked against bcf0da18.

  • One stray mark can dominate parse cost — and trace skipping cut full-corpus reads 6×. In September, one stray backtick pushed a single file from 514 ms to 7,062 ms. With bcf0da18's zero-trace mode, reading all 1,322 tracked .spw files (8.41 MB) dropped from September's 53.3 s (923 files, 839 clean) to 8.55 s (1,311 clean).
  • Shared-parse gaps explain the remaining latency. Even with faster individual parses, CLI corpus commands (census, graph, measure) still key memos on projection options such as hubTop instead of shared content hashes, preventing cross-command reuse.
  • Paths can be checked across the corpus. An integrity walk resolves path citations across the site's .spw surfaces and HTML anchors; upstream spw resolve now classifies citation kinds without misreading prose colons.
  • The editor can show the weaker outline. In WebStorm the plugin draws its own outline and folds with a line scanner, and the editor shows that copy instead of the language server's. One apostrophe inside a backtick sentence, Jake Parker's list, or a mid-line ~#landed leaves a frame that will not fold; the server handles both, though documentSymbol still reparses open buffers.
  • Repetition costs the reader more than the parser. A month of drawing prompts repeated one plate of instructions 31 times, 41% of the file. Taking it out made the parse 11% faster; writing the days as record rows made it 58% slower. A slower parse is worth a form that reads cleanly when a project schedules which surfaces are parsed on save vs. on demand.
  • One command said something new. The report singles out spw form --stdin as "the only command that said something countable-by-hand was not already known," establishing the contour template that spw fingerprint later brought to single expressions.
