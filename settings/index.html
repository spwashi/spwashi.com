Runtime Map

Settings are not isolated form fields. They flow into datasets, CSS variables, event bus diagnostics, and progressively enhanced modules. Module readiness, cauldron phases, and cadence discovery follow the same rule: explicit state first, visual response second.

Component composition is inspectable

The Settings page now labels representative regions as stages, folds, choice fields, readouts, token cards, and query labs. JavaScript can read those labels, measure their boxes, and return a short story about whether a component is present, waiting, or overfull.

This makes the page useful as a practice surface: an author can ask what a component is doing before changing copy, spacing, color, timing, or enhancement behavior.

spwCompose.controls.composition.inspect('#runtime-map')

1. Normalize

Stored values are merged with defaults and checked against allowed options.

normalizeSiteSettings(storage.get())

2. Derive

Settings become author, climate, typography, motion, grain, ecology, semantic, field, and wonder modifiers.

deriveArchitecturalModifiers(settings)

3. Apply

Datasets and CSS variables are written to the document root and body.

document.documentElement.dataset.spw*

4. Emit

Canonical bus events announce settings, author mode, development shifts, and deviations.

bus.emit("settings:changed", settings)

5. Warm

Eligible modules declare whether they were considered, prefetched, cached, or deferred by connection posture.

window.__SPW_SITE__.discoverRuntimeResources()

Treat sigils and brace expressions as small handles, not mandatory detours. Hover, focus, or a deliberate hold will preview a handle. Use ?, Alt+Enter, a context click, or a longer touch hold to open the menu on purpose without changing where an ordinary route goes.
