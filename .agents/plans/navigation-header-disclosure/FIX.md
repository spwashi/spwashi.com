# Navigation Header Disclosure Affordance Fix

## Failures

- The attention posture header pill can read like a favorites/bookmark surface when its label is stale or too generic.
- The posture values were abbreviated enough that `breath / field / horizon` did not explain the self/local/global attention relation.
- The constrained header disclosure label `Tune` hid text size, color, contrast, layout, and inspection controls behind a vague verb.
- Clicking the posture pill still felt like clicking a status indicator that unexpectedly navigated away from the current page.

## Diagnosis

- Header actions are generated by `scripts/template.mjs`, then runtime-synced by `public/js/runtime/shell-disclosure.js`; both layers need clear copy so live mutation cannot drift from the template.
- The shell utility controls are only exposed in toggle/constrained modes, so the disclosure summary needs to carry more meaning without adding another header row.
- The issue is hierarchy and affordance clarity, not a new navigation state machine.
- The posture control should not pretend to be a link if JavaScript intercepts activation; a button plus an explicit settings link keeps tab order and semantics predictable.

## Planned Fix

- Label the posture pill as `Attention posture` in the template.
- Sync full attention relation labels in the runtime and expose the current posture through `aria-label` and `title`.
- Rename the shell utility disclosure from `Tune` to `Display`, with accessible detail naming text size, color, contrast, layout, and inspection.
- Keep the mobile collapse behavior, but adjust the attention pill width slightly so fuller labels have room before truncating.
- Convert the posture pill to a preview button under the shell runtime and place a normal `Open settings` link inside the panel.

## Deferred Follow-Ups

- Verify on the live deployed build that no stale `FAVORITES` header label remains after the next publish.
- Revisit mobile header hierarchy only if route actions, cauldron, posture, and display controls still compete after this copy-level clarification.
- Consider page-aware de-emphasis for Cauldron on `/play/` after the preview interaction proves stable.
